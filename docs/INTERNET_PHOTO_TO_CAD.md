# Интернет-фото → CAD

Основной маршрут DA3-CAD принимает несколько ракурсов одного неподвижного
предмета и выдаёт редактируемый CadQuery, один проверенный STEP solid, STL,
параметры и полный provenance.

```text
RGB → DA3-LARGE-1.1 (depth/confidence/K/E)
    → маски объекта
    → 3D fusion и каноническая ориентация
    → silhouette/depth visual hull
    → cuboid B-Rep
    → безопасная проверка CadQuery
    → model.py + STEP + STL + отчёты
```

## Как снимать

Оптимальный практический вход — 12–24 кадра:

- один и тот же физический объект, геометрия не меняется;
- объект целиком виден и находится примерно в центре;
- соседние ракурсы имеют большое перекрытие;
- камера обходит объект, зум и фокус фиксированы;
- есть боковые, верхние и несколько нижних наклонных видов;
- нет сильного motion blur, пересветов и движущихся частей.

Случайные фотографии похожей модели из разных магазинов не образуют корректную
многовидовую последовательность: экземпляры, объективы и скрытые варианты
геометрии могут различаться. Сначала нужно отобрать согласованный набор одного
объекта.

## Запуск только по RGB

```bash
da3-cad doctor photos/
da3-cad reconstruct photos/ \
  --output outputs/object-rgb \
  --config configs/internet_photo.yaml \
  --accept-noncommercial-weights
```

DA3 оценивает глубины и камеры, а маска строится автоматически. Если фон сложный
или маска неверна, подготовьте бинарные PNG с теми же именами:

```bash
da3-cad reconstruct photos/ \
  --output outputs/object-masked \
  --config configs/internet_photo_masked.yaml \
  --masks masks/ \
  --accept-noncommercial-weights
```

## Камеры и масштаб

Внешние камеры обычно повышают устойчивость:

```bash
da3-cad reconstruct photos/ \
  --output outputs/object-calibrated \
  --config configs/internet_photo.yaml \
  --cameras cameras.npz \
  --accept-noncommercial-weights
```

COLMAP и any-view DA3 не дают гарантированного физического масштаба. Чтобы
получить миллиметры, передайте один действительно измеренный именованный размер:

```bash
--known-dimension body_width=120mm
```

Без такого свидетельства результат честно помечается как
`canonical-model-unit`.

## Что происходит после RGB

1. DA3-LARGE-1.1 выдаёт для каждого вида z-depth, confidence, `K` и
   world-to-camera `E`.
2. Автоматическая сегментация ищет ближний центральный компонент, локально
   уточняет его GrabCut и сохраняет маски/overlay.
3. Пиксели разворачиваются в 3D; маска и per-view confidence отбрасывают фон и
   слабые измерения.
4. Облако проходит outlier и multi-view consistency фильтры, затем
   детерминированно ориентируется.
5. Voxel остаётся, если его проекция поддержана достаточным числом силуэтов;
   DA3-depth консервативно вырезает пространство перед видимой поверхностью.
6. Сохраняется крупнейшая связная компонента, после чего её покрывают
   непересекающимися cuboid features.
7. Генерируется параметрический CadQuery с `body_width`, `body_depth`,
   `body_height`; код выполняется в ограниченном subprocess.
8. STEP принимается только как один solid с конечным положительным объёмом.
9. Результат сравнивается со входным облаком и всеми масками. Это проверка
   согласованности со входом, а не точность относительно неизвестного CAD.

## Реально проверенный интернет-пример

24 кадра видео камеры Google Objectron, 24/24 камеры COLMAP,
DA3-LARGE-1.1, автоматические маски:

- 397 184 слитых точек;
- 60 cuboid features;
- один валидный STEP solid, fallback не использовался;
- mean input silhouette IoU 81,61%;
- trimmed mean input silhouette IoU 81,84%;
- input CD² 0,02010;
- физический масштаб и точность к исходному CAD неизвестны.

Это интеграционный пример, не benchmark по категориям. Подробности и команды —
в [`RESULTS.md`](RESULTS.md).

## Что пока нельзя обещать

- точную скрытую геометрию из одного фото;
- исходное дерево операций и design intent;
- надёжные отверстия, карманы, фаски, скругления и паттерны для любой детали;
- резьбы, допуски, посадки, GD&T, материалы и сборки;
- миллиметры без калибровки или известного размера;
- производственную точность без сравнения с reference CAD/метрологией.

RTX 5080 16 ГБ достаточна для текущего inference. H100 полезна для будущего
обучения распознавания CAD-features и больших benchmark-прогонов.
